# Submission checklist

## Already prepared

- On-device Gemma worker, pinned model/runtime, offline app shell.
- Explicit non-AI preset option; no silent fallback or mislabelled model output.
- Persistent draft/journal, optional local photos, editable reflection, text/JSON exports.
- Walk timing ends before note-taking; Page Visibility limitations are disclosed.
- Unit/browser tests, real-model probe, Render Blueprint, GitHub Actions, MIT application licence and third-party credits.
- DEV article structure and a short demo script.
- Public [GitHub source](https://github.com/sneaxhuh/pocket-wild), passing Actions, and live [Render app](https://pocket-wild.onrender.com/) in the submitter's workspace.
- Automated hosted Gemma generation, cold offline reload, evidence export, and journal restoration; see [testing](testing.md). These are not outdoor observations.

## Needs the submitter

1. **Eligibility:** confirm you are eligible under the challenge rules (including age 18+). GitHub publication and Render deployment are already complete; no account setup is required for the current deployment.
2. **Phone check:** open the final public URL in your intended browser on Wi-Fi, download Gemma, generate a card, reload, load the cached model, then repeat with airplane mode enabled. Record phone/browser and failures honestly. Storage and WebGPU behaviour differ by device.
3. **Real outdoor test:** take a 10-minute walk or seated outdoor pause. Start the timer, lock the phone, return, enter three things you actually noticed, and export evidence JSON. Photograph the surroundings if safe and permitted; avoid bystanders/private details. Do not fabricate outdoor results from automated fixtures.
4. **Demo:** record a 60–90 second video showing surroundings → Gemma card → phone locked/outdoors → reflection → offline reload and inference → evidence. A prerecorded time cut is fine if disclosed.
5. **Article:** replace every `TODO` in [the draft](dev-submission.md), add the public demo/repository/video links and genuine outdoor results, and review the English prose. Use the challenge's submission template and tags `devchallenge`, `hf26challenge`.
6. **Tracks:** list **Best Use of Gemma** and **Best Use of Render**, which now have tested implementations and a live deployment. Overall consideration is automatic. The passing Actions workflow supports **Best Use of GitHub Copilot** only under the published Actions criterion; describe it as Actions, not Copilot assistance.
7. **Publish before deadline:** October 11, 2026 at 11:59 PM PDT = October 12 at 12:29 PM IST. Recheck the [official challenge rules/page](https://dev.to/challenges/hacktoberfest-week1-2026-10-05) before posting. Repositories/projects must be new in the challenge window. Note post-deadline commits in README.

Only one prize can be won per submission. Partner use should be meaningful and accurately described; browser speech synthesis is not ElevenLabs, local evidence is not Sentry, and local IndexedDB is not Atlas.
